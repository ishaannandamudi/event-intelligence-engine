# Final attack surface and security boundary

EIE's source text, source metadata, model output, URLs and labels are untrusted inert data. The extraction verifier requires source evidence for accepted factual fields. Fake system/tool/shell/credential/URL instructions do not invoke code, tools or requests. Unsupported numeric/entity/time/status upgrades are rejected by the existing EIE-12 owner. Final snapshots reference its accepted/rejected audits; they do not add a model executor or relax evidence verification.

The final service uses strict JSON with duplicate-key refusal, closed request fields and typed primitives. Body, array, identity, reference, batch, expansion and output bounds are enforced. Native tables are selected from a static owner allowlist; identifiers are SQL parameters. No endpoint accepts filesystem paths, query SQL, archive names, arbitrary URLs or source-controlled type imports. Expansion requires membership in a frozen snapshot and exposes supported native detail, with no raw document text endpoint. Consumers must also treat expanded labels/URLs as inert.

The optional HTTP adapter binds IPv4 loopback only. It has one active worker, bounded backlog and socket timeouts, rejects duplicate Content-Length and Transfer-Encoding framing, closes responses, disables base access logging, emits JSON with nosniff, and adds no wildcard CORS or fake authentication. It has no built-in remote authentication/TLS, multi-tenant permissions or production rate-limiting gateway. Operator CLI file paths and backup/restore paths are trusted local configuration; they are not HTTP inputs.

Operational logs contain fixed operation/status categories, counts, durations, safe snapshot IDs and hashes of correlation IDs. They contain no exception messages, request bodies, credential prompts, source bodies or huge payloads. Metrics do not affect snapshot identity. Secrets are not required by the offline service; optional live-ingestion credentials retain their earlier runtime boundaries.

Typed owner references are verified before publication. Normal collection checks publication/member indices, typed manifests and SHA-256 of retained native owner bytes. Deep validation delegates to upstream graph, NLP, intelligence, study, impact, analogue, interaction and reliability auditors. Invalid/corrupt data fails closed; it is not silently recomputed from current data. Startup validates exact migration DDL; readiness checks current schema, readable tables, physical/FK integrity and configured catalogs. Immutability triggers protect final retained rows. This is integrity validation, not authentication against a malicious DB administrator.

Backup uses the SQLite backup API under the store lock, validates the consistent copy, creates an exclusive output with private temporary permissions and refuses existing/symlink outputs. Restore verifies a copied regular file before exposing a new destination. Archive directories and commercial entitlements require separately retained operator backups; a database copy does not grant source redistribution permission.

The full offline suite is run with socket connection calls blocked. No import, test fixture or snapshot query enables live acquisition. Existing transport security controls and [NLP security](nlp-security.md) continue to apply.
